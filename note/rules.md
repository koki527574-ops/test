# 記事生成ルール

## 1. 記事候補の選定基準

### 通過フィルタ（1つでもNoなら不採用。他の候補を探す）

1. 対応する実体験ストックIDがあるか
2. 曜日に必要な「濃さ」を満たしているか（月火金=大／木=中／水日=小）
3. 過去記事と主題が重複していないか（→ 4章の重複チェック）
4. この記事を読む具体的な人物像が1つ以上思い浮かぶか
5. 読者獲得か販売のどちらかにつながるか

**5がNoの記事は書かない。** 本数を埋めるための記事は禁止。

### スコアリング（通過した候補を各5点で採点、高い順に曜日へ割り当て）

| 観点 | 5点の状態 | 1点の状態 |
|---|---|---|
| 具体性 | 数字・固有名詞・手順がある | 抽象論のみ |
| 失敗/未解決 | うまくいかなかった事や未決着が主題 | 成功談のみ |
| 本人性 | 本人にしか書けない | 誰でも書ける一般論 |
| 引き | タイトルで続きが読みたくなる | 読まなくても内容が分かる |
| 新規性 | 過去記事と切り口が明確に違う | 過去記事の言い換え |

同点の場合は「失敗/未解決」が高い方を優先する。このアカウントで一番読まれる型のため。

---

## 2. 本数の決定

| 条件 | 本数 | 内訳 |
|---|---|---|
| 濃さ「大」の未使用ストックが3件以上 + 「小」が2件以上 | **7本** | 月火水木金土日 |
| 濃さ「大」が2件以上 | **5本（基本）** | 月火木金土 |
| 濃さ「大」が1件以下 | **5本未満**。不足を明示して本人に確認 | — |

**水・日は増量枠。** 余裕がある週だけ足す。埋めるために薄い記事を作ることは禁止。

本数が足りない週は、記事を creating する前に「何が足りないか」を出力して止まる。

---

## 3. 無料 / 有料の判定基準

### 有料にする条件（**全部**満たす時のみ）

1. 使用ストックの「数字・固有名詞」が埋まっている
2. 再現可能な手順、または金額・期間などの実数がある
3. 無料部分だけを読んでも独立した価値がある構成にできる
4. 同じ内容を過去に無料で書いていない

**1つでも欠けたら無料にする。** 薄い有料記事は返金・信用低下に直結するので、出さない方が得。

その週に条件を満たすストックが無ければ、**その週は有料記事ゼロ**。全部無料5本にする。これは失敗ではなく正常動作。

### 価格

| 状況 | 価格 |
|---|---|
| 販売実績 0〜3本 | **300円** |
| 購入率3%以上が2週続いた | 500円 |
| 有料記事が8〜10本たまった | 定期購読マガジン 500円/月 へ移行（単発と並行） |

読者が少ないうちに高値をつけない。検証にならない。

### 有料ラインの位置

- 無料部分: 何が起きたか / どう思ったか / 結果どうなったか（**ここまでで記事として完結させる**）
- 有料部分: 具体的にどうやったか / いくらかかったか / 何が壊れたか / 手順・設定値

「続きは有料で」と書いて切らない。無料部分の最後は問いや結論で閉じ、有料部分は「実際の中身」として独立させる。

## 4. 重複チェックルール

`note/published-index.md` を参照して機械的に判定する。

| 条件 | 判定 |
|---|---|
| 同じ主題タグの記事が**過去30日に2本以上** | 不採用 |
| 同じ主題タグが**過去90日に1本以上** | 切り口の違いを1行で説明できれば採用。できなければ不採用 |
| 過去記事とタイトルの主要語が2語以上一致 | タイトルを作り直す |
| 過去記事と導入の型が同じ かつ 主題タグも同じ | 導入の型を変える |

さらに、**同じ週の中で同じ導入の型を2回使わない**（下記）。

### 導入の型（週内で使い回さない）

| 記号 | 型 | 例 |
|---|---|---|
| A | 結果から入る | 「〜を使うのをやめた。」 |
| B | 場面から入る | 「〜していた時に、〜が起きた。」 |
| C | 疑問から入る | 「〜なのか、まだ分かっていない。」 |
| D | 否定から入る | 「〜だと思っていた。違った。」 |
| E | 数字から入る | 「〜日かかった。」 |
| F | 実在の会話から入る | **実際の会話がストックにある時のみ使用可** |

前週に使った型の並びは `note/learning.md` に記録し、翌週は同じ並びを避ける。

## 5. タイトル生成ルール

記事1本につき**3〜5個**出す。1個目を推奨案とし、残りを代替案として併記する。

### 作り方

- 3案以上出す時、**必ず異なる型**にする（下表から別々に選ぶ）
- 検索キーワードよりも「読みたくなるか」を優先する
- 煽らない。「衝撃」「ヤバい」「絶対」は使わない
- 数字は実際にストックにある数字のみ使う。盛らない

| 型 | 例 |
|---|---|
| 告白型 | 「作れるようになったけど、売れなかった」 |
| 問い型 | 「AIで作れることと、売れることは何が違うのか」 |
| 否定型 | 「自動化をやめた」 |
| 数字型 | 「◯日かけて作った仕組みを使わないことにした」 |
| 対比型 | 「技術より、値段を決める方が難しい」 |

### 禁止語（タイトル・本文とも）

```
結論から言うと / 〜について解説します / 重要なのは / 大きく3つあります
つまり / 要するに / ここで学んだのは / 今回のポイントは / 最後にまとめると
AIを活用することで / 効率化できます / 生産性が上がります
革新的 / 画期的 / 誰でも簡単に / いかがでしたか
```

### 文章の禁止事項

- 同じ内容を言い換えて繰り返す
- 各段落をきれいにまとめる
- 最後に必ず前向きな教訓をつける（**未解決のまま終わってよい**）
- 読者に説教する・上から教える
- 箇条書き中心にする（箇条書きは1記事2ブロックまで）
- 抽象論だけで終わる

## 6. Threads用投稿の生成ルール

記事1本につき1投稿。公開日の**朝**に投稿する想定で作る。

### 作り方

1. 記事本文から**一番生々しい2〜3行を抜き出す**（要約しない。原文に近い形で切る）
2. 140〜300字程度に収める
3. **リンクは本文に入れない。** 「詳しくはnoteに書いた」等の誘導文も入れない
4. 投稿文の末尾は言い切らず、余白を残す
5. リンクはリプライ欄またはプロフィール欄に置く（本人が手動で）

### 例外

- 金曜の有料記事: Threadsには**木曜の無料記事**を流す。有料記事に直接誘導しない
- 土曜の回遊記事: Threadsは作らない（既存読者向けのため）

---

## 7. 木曜記事の特別ルール

木曜は金曜有料記事の宣伝記事にしない。

- **木曜単体で最後まで読んで価値がある記事にする**
- 金曜への言及は記事末尾の1行のみ
- **判定基準: その1行を削除しても記事が成立すること。** 成立しないなら書き直す
- 「続きは明日」「詳細は有料で」という書き方をしない
- 金曜への導線は「同じ領域のより具体的な実践記録が明日ある」という事実の提示にとどめる
