# 今週分の記事セットを作る

目的は記事を作ることではなく、**売れる記事の型を毎週1つずつ学習すること**。
本数を埋めることを目的にしない。材料が無ければ減らすか止める。

## 絶対ルール

- **架空の体験を書かない。** `note/experience-stock.md` に無いことは書かない
- 実際に経験していないことを一人称で書かない
- 材料が足りない時は、創作して埋めず、**不足している材料を明示して止まる**
- 薄い記事を本数合わせで作らない
- 1週間に検証する変数は**1つだけ**

---

## 自動実行モード

プロンプトで `plan.json` のパスを渡された場合は、VPSからの週次自動実行。以下が変わる。

- **枠はすでに確定している。** Step 2・Step 3 の判定をやり直さない。plan.json の `slots` がその週の全記事
- 各枠の `candidateExpIds` **に無いストックは使わない**。1つのストックを2つの枠に使わない
- `paid` / `priceYen` / `publishAt` / `articleFile` は plan.json の値を使う。書き換えない
- 人間への質問で止まらない。材料が足りない枠は飛ばし、`missingMaterial` に理由を残す
- 生成物は指定された実行ディレクトリに保存する

材料が足りないことを理由に、**ストックに無い出来事を書いて枠を埋めることは禁止**。枠を減らして終える。

## 手順

### Step 0. 読み込み（必ずこの順で、書き始める前に全部読む）

1. `note/learning.md` — **最初に読む。** 「次週への申し送り」と「確定した型」「否定された型」を今週の生成に適用する
2. `note/published-index.md` — 重複チェックの根拠
3. `note/experience-stock.md` — 使える材料
4. `note/rules.md` — 判定基準
5. `note/templates.md` — 曜日別の書き方

learning.md を読まずに書き始めない。読まなければ先週の学習が捨てられ、ただの量産になる。

### Step 1. 今週の材料を受け取る

ユーザーが渡した「その週に起きたこと」を `note/experience-stock.md` の書式に変換して追記する。

- 事実と感想を分ける
- 「その時どう思ったか」をユーザーが言っていなければ**空欄のまま残す**。推測で埋めない
- 濃さ（大/中/小）と主題タグを付ける

ユーザーが何も渡していない場合は、既存の未使用ストックだけで進む。

### Step 2. 本数を決める

`note/rules.md` の2章に従う。

- 濃さ「大」3件以上 + 「小」2件以上 → 7本
- 濃さ「大」2件以上 → 5本（基本）
- 濃さ「大」1件以下 → **記事を書き始める前に止まり、不足を報告する**

### Step 3. 不足チェック（ここで止まる可能性がある）

以下を確認し、足りなければ**記事を書かずに**報告する。

- 月・火・金に使うストックの「その時どう思ったか」が埋まっているか
  → 空欄なら、その記事は書けない。ユーザーに「この時どう思ったか」を質問として出す
- 有料記事に使うストックの「数字・固有名詞」が埋まっているか
  → 空欄なら**その週は有料記事を作らない**（無料5本にする）

報告の書式:

```
【不足している材料】
- EXP-00X（月曜に使う予定）: 「その時どう思ったか」が空欄。
  質問: 〜をしていた時、実際にどう感じましたか？
```

不足があっても、**書ける分は書く**。全部止めない。

### Step 4. テーマ選定と重複チェック

`note/rules.md` 1章のフィルタとスコアリングで候補を絞り、曜日に割り当てる。
`note/rules.md` 4章で重複判定する。候補一覧はユーザーに見せない。決めたものだけ出す。

導入の型は週内で重複させない。learning.md の使用履歴を見て前週と同じ並びも避ける。

### Step 5. 執筆

`note/templates.md` の曜日別構成に従う。

木曜は特に注意: **末尾の金曜への1行を消しても記事として成立すること。** 成立しないなら書き直す。

書いた後、以下を自分で確認してから出す。

- 禁止語（rules.md 5章）が入っていないか
- 同じ内容を言い換えて繰り返していないか
- 各段落をきれいにまとめていないか
- 最後に前向きな教訓を足していないか
- 説教口調になっていないか
- 箇条書きが2ブロックを超えていないか
- 短い段落と長い段落が混ざっているか
- 一人称が「僕」で統一されているか

### Step 6. 今週の検証変数を決める

learning.md の「検証できる変数の一覧」から**1つだけ**選ぶ。
前週の結果が「判断できない」だった場合は、**同じ変数をもう1週続ける**。

選んだ変数と仮説を出力に明記する。

### Step 7. 出力

記事ごとに、以下をこの順で出す。ユーザーはこれをnoteにコピペするだけで済む状態にする。

```
━━━━━━━━━━━━━━━━━━━━
【◯曜日】役割 ｜ 無料 or 有料300円
予約日時: MM/DD(◯) HH:MM

■ タイトル（推奨）
　〜〜〜
■ タイトル代替案
　2. 〜〜〜（型）
　3. 〜〜〜（型）
　4. 〜〜〜（型）

■ 本文（ここからコピペ）
　（全文）

■ 有料ライン位置 ※有料記事のみ
　「〜〜〜」の直後で切る

■ タグ（2〜4個）
　#〜 #〜 #〜

■ 見出し画像案
　（内容に合う画像の指示。文字入りでなくてよい）

■ Threads投稿（MM/DD 朝）
　（140〜300字。リンク・誘導文なし）

■ 使用EXP / 主題タグ / 導入型
━━━━━━━━━━━━━━━━━━━━
```

最後にまとめて出す:

```
【今週の検証】
変数: 〜〜　仮説: 〜〜　測り方: 〜〜

【不足している材料】
（あれば）

【公開後にやること】
- published-index.md に◯行追加
- 日曜に review/TEMPLATE.md をコピーして記入
```

### Step 8. 台帳の更新

- `note/experience-stock.md`: 使ったストックを「使用済み」にする（URLは公開後に本人が記入）
- `note/experience-stock.md` の「不足している材料」欄を更新する
- `note/published-index.md`: 予定行を追加（URLと数字は公開後）
- `note/learning.md`: 「検証中」に今週の仮説を追加、導入型の使用履歴に追加

## 週次レビューを頼まれた時

「今週のレビュー」「振り返り」等と言われたら:

1. `note/review/TEMPLATE.md` をコピーして `note/review/YYYY-Wnn.md` を作る
2. ユーザーに数字を聞く（総ビュー / スキ / フォロワー増 / 有料ビュー / 購入数）
3. 記入し、検証結果を判定する
4. **`note/learning.md` の「次週への申し送り」を書き換える**（ここが翌週への唯一の接続点。必ずやる）
5. 確定した型 / 否定された型 の表に移す
